# 設計決定事項（DESIGN.md）

このファイルは Web アプリ版の全設計決定を網羅的にまとめた **正典** です。  
判断の経緯（なぜそうしたか）は `DECISIONS.md` を参照してください。

最終更新: 2026-05-12

---

## A. アーキテクチャ

### A-1. ffmpeg は削除

- AssemblyAI が mp3 / mp4 / m4a / wav / aac / flac など主要形式を直接受け取れる
- ユーザーが扱う形式は mp3 と mp4 が中心と判明
- 対応外の形式が来た場合は「mp3 か mp4 に変換してください」とエラー表示

### A-2. 進捗UI設計

- **アップロード中**: 「音声をアップロード中... 35%」（バイト数基準の正確な %）
- **AI 処理中**: 「文字起こし中... 残り約 4 分」（音声長から推定した残り時間、動作中アニメ付き）
- **結果取得中**: 「結果を取得中...」（数秒）
- **完了時**: macOS / OS の通知センターで「文字起こしが完了しました」

### A-3. オフライン時の挙動

- 処理開始時にネット未接続なら「インターネット接続を確認してください」とエラー
- 起動時の特別なチェックは不要（社内利用が中心でネット断は稀）
- キュー機能は実装しない（複雑化に見合わない）

### A-4. プライバシー

- AssemblyAI で処理完了後、即座に削除依頼を送る
- AssemblyAI のサーバーには処理中の数分間だけ残る
- リージョンは US 標準（AssemblyAI は SOC2 / GDPR 準拠、学習データ非利用）
- **Web 版での追加対応**: 自社サーバー上でも音声を処理完了後に即削除

## B. 機能

### B-1. モデル選択

- UI で「高精度（Universal-2 / Best）」と「コスト重視（Nano）」が選択可能
- デフォルトは「高精度」
- 各選択肢の横に「1時間あたり約55円」「1時間あたり約20円」と表記

### B-2. コスト表示

- **処理完了時**: 「今回の利用料金: 約 110円（2時間4分）」と表示
- **設定画面**: 月次累計を表示（処理時間・概算料金・処理本数）
- 「約」と明記して期待値を調整
- 月初に自動リセット
- Web 版では **サーバー側で一元管理** され、より正確

### B-3. 古い HuggingFace Token の自動削除

- 新バージョン初回起動時に Keychain 内の `co.lionheart.noto / hf_token` を自動削除
- 旧 `config.json` 内の平文トークンも削除
- **Web 版**: Keychain は使わない（ブラウザベース）ので、この処理自体が不要

## C. 運用安全

### C-1. AssemblyAI 支出上限

- AssemblyAI ダッシュボードで月 5,000円（約35ドル）を上限設定
- これはユーザー（開発者）が管理画面で設定する作業
- API キー流出時の被害金額を限定する保険

### C-2. 長尺音声への警告

- 3時間を超える音声を選択した場合に確認ダイアログを表示
- 「この音声は約 N 時間です。約 NN 円かかります。続けますか？」
- 操作ミスでの誤処理を防止

## D. 設計補完

### D-1. 既存ファイル互換

- 既存の `.transcription.json` 形式は維持
- `Segment` データ構造（start, end, speaker, text, display_name）はそのまま継承

### D-2. ウェブビュー版（旧 `app_web.py`）の扱い

- Mac アプリ版時代の試作物（`app_web.py` と `frontend/` フォルダ）は削除
- 設計思想が今回の Web アプリと大きく異なるため、無理な再利用はしない

### D-3. 話者ラベル正規化

- AssemblyAI が返す A/B/C 形式を内部で SPEAKER_00/01/02… に正規化
- UI 側のコードは変更不要

### D-4. エラーメッセージ

| エラー | 表示 |
|---|---|
| API キー未設定 | 「設定画面で AssemblyAI API キーを入力してください」 |
| API キー無効 | 「API キーが正しくありません」 |
| ネット未接続 | 「インターネット接続を確認してください」 |
| 形式非対応 | 「mp3 か mp4 をご利用ください」 |
| ファイル不在 | 「ファイルが移動・削除された可能性があります」 |
| API エラー | 「文字起こしサービスでエラーが発生しました。時間をおいて再試行してください」 |
| 月上限超過 | 「今月の利用上限に達しました。管理者にご連絡ください」 |
| タイムアウト | 「処理に時間がかかっています。ネット接続を確認して再試行してください」 |

### D-5. ファイルサイズ上限

- 上限: 2GB
- UI に常時案内表示: 「対応ファイルサイズ：2GBまで（約2時間の動画ファイル相当）」
- 上限超過時: 「このファイル（XX GB）は上限を超えています。2GB 以下のファイルを選んでください」
- 緩和の必要が出てきたら別途検討

## E. 中核アーキテクチャ

### E-1. 完全非同期設計

- 「ジョブを投げて、後で結果を取りに行く」を中核に据える
- スリープ防止は実装しない（OS と戦わない）
- ジョブ ID をローカル / サーバーに保存
- 中断時（スリープ・クラッシュ・電源切れ・アプリ閉じ）は次回起動時に自動復帰
- Web アプリでは「ブラウザを閉じても処理は継続、後でアクセスすれば結果あり」が自然に実現

## F. 話者編集 UI

### F-1. Notta 風のドロップダウン式話者編集

- 話者名クリック → 検索可能なドロップダウンが開く
- 候補リストは **全過去ファイルから集めた話者名**（最近使った順）
- 各候補に **名前の1文字目をカラー円で表示**（アイコン）
- 候補をクリックすると **「この話者にのみ適用」「すべての XXX に適用」** の2択メニュー
- 「すべての XXX に適用」は **表示名ベース** で動作（複数の内部ラベルにまたがる場合も対応）

### F-2. 未設定話者の表記

- 「SPEAKER_00」のような技術的表記をやめる
- 「未設定話者1」「未設定話者2」… のように表示（Notta と完全に揃える）

### F-3. 編集モード

- ダブルクリックで編集モード（既存の挙動を維持）
- グローバル編集モード（全カードが編集可能になる方式）
- これは Notta と同じ思想なので変更不要

## G. プラットフォーム（重要な後付け決定）

### G-1. Web アプリとして実装

- Mac アプリではなく、**ブラウザベースの Web アプリ** として実装する
- 動機: 直行直帰・出張先・コワーキングスペースなど場所を問わずアクセスしたい
- 「ファイルをアップロードしておけば、勝手に処理されて後で見られる」体験

### G-2. ホスティング

- マネージドクラウドサービスを使用（Railway / Render / Fly.io 等から選定）
- 月額目安: 500〜2,000円程度
- SSL・OS パッチ・バックアップ等は自動化される選択肢を採用
- サーバー運用知識は最小限で済むサービスを選ぶ

### G-3. 認証

- **Google SSO**（Google Workspace 連携）
- 社内ドメイン（例: `@lionheart.co.jp`）のみアクセス可能に制限
- 退職者対応は Google Workspace 管理画面で完結

### G-4. データ保存

- 文字起こし結果はサーバー側 DB に保存
- ユーザーはいつでもアクセスして閲覧・編集可能
- 保持期間は要詳細設計（永続 or X日 で要判断）

### G-5. ファイルの流れ

```
ブラウザ → 自社サーバー → AssemblyAI
                ↓
            結果保存（音声は即削除）
                ↓
ブラウザ ← 自社サーバー（結果取得）
```

## H. UI/UX 改修（Tier 1 = 必須レベル）

### H-1. 設定の階層化

- メイン画面から「モデル」「言語」などの選択肢を撤去
- 設定画面（歯車アイコンで開く）に移動
- メイン画面に残すのは「ファイル投入」と「開始ボタン」のみ

### H-2. 過去の文字起こし履歴一覧

- 左ペインに履歴セクションを追加
- ファイル名・日付・話者数・長さなどを表示
- クリックで即座に開ける
- Notta が圧倒的に勝っていた部分の解消

### H-3. 編集モードの設計

- ダブルクリック → グローバル編集モード（既存と同じ）
- Notta と同じ挙動なので変更不要
