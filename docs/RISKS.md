# リスク・レジスター（RISKS.md）

このファイルは Web アプリ運用において想定されるリスクと、その対策を整理した一覧です。

最終更新: 2026-05-12

## 評価基準

- **影響度**: 大 / 中 / 小
- **発生確率**: 高 / 中 / 低
- **優先度**: 影響度 × 発生確率（直感的な総合判断）

---

## 🔴 重大リスク（最優先で対策）

### R-01. AssemblyAI 障害でサービス全体が停止

- **影響度**: 大（社員全員が文字起こしできない）
- **発生確率**: 低（AssemblyAI の SLA は高い）
- **検知**: 文字起こしエラーが連続発生
- **対策**:
  - エラー時に分かりやすいメッセージを表示（「文字起こしサービスに障害が発生しています」）
  - AssemblyAI のステータスページ URL を案内に含める
  - 障害が長引く場合の手動連絡ルートを定めておく
  - **長期的**: 別サービス（Deepgram など）へのフォールバック検討（将来課題）

### R-02. ホスティングサービスの障害

- **影響度**: 大（アプリにアクセスできない）
- **発生確率**: 低〜中（マネージドサービスでも年数回は起きうる）
- **検知**: ユーザーから「アクセスできない」報告
- **対策**:
  - 監視ツール（UptimeRobot 等の無料サービス）で稼働状況を5分ごと確認
  - 障害時に開発者（あなた）に通知が飛ぶ仕組み
  - 復旧手順を `OPERATIONS.md` に記載予定
  - ホスティングは SLA 99.9% 以上のサービスを選ぶ

### R-03. API キーの流出による不正利用

- **影響度**: 大（高額の API 料金発生）
- **発生確率**: 低（サーバー内に保管・コードから分離）
- **検知**: AssemblyAI ダッシュボードでの異常な利用量
- **対策**:
  - AssemblyAI 側で **月間支出上限 5,000円** を設定（C-1 で決定済み）
  - 環境変数で管理、Git にコミットしない
  - 流出が疑われたら即座にキーを無効化＆再発行
  - 環境変数を覗ける人を最小限に絞る（ホスティングの管理画面アクセス権）

### R-04. お客様情報の漏洩

- **影響度**: 大（信用失墜、法的責任）
- **発生確率**: 低（対策をすれば）
- **検知**: 通常は検知困難（事後発覚が多い）
- **対策**:
  - 通信は全て HTTPS で暗号化
  - サーバー側の音声ファイルは **処理完了後に即削除**（A-4 方針）
  - AssemblyAI 側も削除依頼（A-4 方針）
  - DB 上の文字起こし結果は適切なアクセス制御
  - 不正アクセス検知（ログイン失敗の連続など）
  - 退職者対応は Google Workspace 管理画面で即時無効化

## 🟡 中程度リスク（適切な対策が必要）

### R-05. 想定コスト超過

- **影響度**: 中（金銭的損失）
- **発生確率**: 中（ユーザーが大量に使う可能性）
- **検知**: AssemblyAI ダッシュボードの利用量、月次累計表示
- **対策**:
  - **月間支出上限**で硬く制限（R-03 と同じ）
  - 各処理後に料金表示（B-2 方針）
  - 設定画面に月次累計表示（B-2 方針）
  - 上限が近づいたらアラート通知（実装フェーズで設計）

### R-06. Google Workspace の仕様変更で認証が動かなくなる

- **影響度**: 中（社員全員ログイン不可）
- **発生確率**: 低（後方互換性は通常守られる）
- **検知**: ログインエラーの多発
- **対策**:
  - OAuth ライブラリは公式 SDK を使う（自前で実装しない）
  - 仕様変更の通知に注意（Google からのメール）
  - 万一の場合のためにメール＋パスワード認証を予備として実装する案も検討

### R-07. ファイルアップロード失敗（ネット切断・タイムアウト）

- **影響度**: 中（ユーザー体験の悪化）
- **発生確率**: 中（特に外出先・大容量ファイル）
- **検知**: ユーザーからの「アップロードできない」報告
- **対策**:
  - 分割アップロード（chunked upload）を実装
  - 失敗時に再開可能にする
  - 進捗表示を正確に
  - エラー時に「再試行ボタン」を表示

### R-08. ブラウザ非互換

- **影響度**: 中（一部社員が使えない）
- **発生確率**: 低（モダンブラウザは大体動く）
- **検知**: 特定の社員からのみ「動かない」報告
- **対策**:
  - サポート対象ブラウザを明示（Chrome / Safari / Edge の最新版）
  - 古い IE などはサポート外と明記
  - 動作確認を複数ブラウザで実施

### R-09. 開発の頓挫

- **影響度**: 大（プロジェクト失敗）
- **発生確率**: 中（複雑な書き換えはリスクあり）
- **検知**: 進捗が止まる、コードがぐちゃぐちゃになる
- **対策**:
  - **ドキュメント駆動**（CLAUDE.md, DESIGN.md, ROADMAP.md）
  - **Git タグでチェックポイント**運用
  - **各フェーズで動く状態**を作る（段階的に進める）
  - **複雑になったらリファクタリング**（複雑さを溜め込まない）
  - 困ったら Mac アプリ版（`v0.1-mac-app-snapshot`）にいつでも戻れる

## 🟢 軽度リスク（認識しておく程度）

### R-10. AssemblyAI の値上げ

- **影響度**: 中
- **発生確率**: 低
- **対策**: 値上げ通知を見て、コスト試算を見直す。必要なら別サービス検討

### R-11. AssemblyAI の精度低下（モデル更新で副作用）

- **影響度**: 小〜中
- **発生確率**: 低
- **対策**: 定期的にサンプル音声で品質確認、ユーザーからのフィードバックを集める

### R-12. データベースの破損・喪失

- **影響度**: 中
- **発生確率**: 低（マネージド DB なら）
- **対策**: 日次バックアップ、復旧手順の確認

### R-13. ライブラリの脆弱性

- **影響度**: 中
- **発生確率**: 中（定期的に発見される）
- **対策**: 依存ライブラリを定期更新、GitHub の Dependabot などで通知

### R-14. 設計判断の誤り（後から「やっぱり別の方が良かった」となる）

- **影響度**: 小〜中
- **発生確率**: 中
- **対策**: 設計判断を `DECISIONS.md` に記録して、いつでも振り返れる状態に。判断を変える場合も記録に残す
